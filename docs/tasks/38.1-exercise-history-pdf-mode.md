## 🔧 Хрупкі місця (обов'язково)

### 1. Логіка PDF

Зверни увагу, що в Задачі 32.1 ми створювали сторінку `/exercise/[id]/pdf-check`. Вона очікує на існуючу вправу. Тому логіка має бути такою: спочатку завантажуємо файл, потім перекидаємо на сторінку перевірки.

### 2. UX завантаження

Коли користувач обирає "Роздрукувати PDF", покажи невеликий індикатор завантаження (спінер) на картці, поки генерується файл.

### 3. Реалізація (що зроблено)

- Новий клієнтський компонент `components/exercise/exercise-mode-menu.tsx`:
  тригер — іконка `Play` з тултипом «Продовжити», під час генерації PDF показує `Loader2` (`animate-spin`).
- Меню лишається відкритим під час генерації (`event.preventDefault()` у `onSelect`), у разі помилки —
  повідомлення «Не вдалося підготувати PDF. Спробуйте ще раз.» всередині меню.
- Завантаження файлу винесено в `lib/exercise/pdf-download.ts`: `fetch` → `blob` → `URL.createObjectURL` →
  `<a download>` (ім'я файлу береться з `Content-Disposition`).
- Бекенд-логіка PDF-режиму (32.1) не змінювалась.

### 4. Видимість дропдаунів (побічно)

Меню зливалося з картками: токен `--popover` у світлій темі був `0 0% 100%` (те саме, що `--card`).
Виправлено через токени в `app/globals.css`: `--popover` → `36 45% 93%` (light) / `30 12% 21%` (dark).
`components/ui/*` не змінювався — зміна глобальна, для всіх dropdown/popover.
