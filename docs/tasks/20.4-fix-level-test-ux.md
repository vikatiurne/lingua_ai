## 🎯 Мета
Зробити тест рівня стійким до помилок. Користувач не повинен втрачати свої відповіді через збій AI, а система має давати можливість повторити спробу оцінки.

---

## ✅ Acceptance Criteria

### 1. Збереження прогресу (State Persistence)
- [x] У компоненті тесту (наприклад, `AdaptiveTest`) додати збереження поточного стану відповідей у `localStorage` (або `sessionStorage`).
- [x] Зберігати стан після кожної відповіді на питання.
- [x] При завантаженні сторінки тесту перевіряти, чи є збережений стан. Якщо є — відновлювати прогрес (показувати те питання, на якому зупинилися).
- [x] Очищати `localStorage` тільки після успішного отримання результату.

### 2. Обробка помилки оцінки (Graceful Failure)
- [x] Якщо API `POST /api/test/submit` повертає помилку (500 або таймаут), **НЕ скидати** сторінку тесту.
- [x] Показати стан помилки: *"Вибачте, сталася помилка при оцінці. Ваші відповіді збережено."*
- [x] Додати кнопку **"Спробувати ще раз"**, яка повторно відправляє збережені відповіді на бекенд.

### 3. Бекенд та Таймаути
- [x] Перевірити таймаут запиту. Оцінка 30+ питань може займати до 15-20 секунд. Переконатися, що фронтенд не обриває запит занадто рано.
- [ ] (Опційно) Якщо AI провайдер повністю недоступний, реалізувати fallback: зберегти відповіді в БД зі статусом `pending_evaluation` і показати користувачу, що результат буде готовий пізніше (або розрахувати базовий бал на основі простої кількості правильних відповідей, якщо це можливо).

## 🔧 Хрупкі місця (обов'язково)

### 1. Управління станом
Не використовуй `localStorage` для зберігання чутливих персональних даних. Зберігай лише `testId`, `currentQuestionIndex` та масив `answers`.

### 2. UI помилки
Банер помилки має бути візуально помітним, але не агресивним. Кнопка "Спробувати ще раз" має мати стан завантаження (спінер), поки йде повторний запит.

## 🧩 Реалізація

- Стан адаптивного тесту серіалізується у `localStorage` під ключем
  `lingua:level-test:state` після старту та після кожної відповіді.
- На монтуванні `TestRunner` відновлює збережений стан, поточне питання або
  наступне доступне питання; пошкоджений/застарілий стан відкидається.
- Відправка результату має клієнтський таймаут 45 с (`AbortController`), а
  роут `POST /api/test/submit` — `maxDuration = 60`.
- Після помилки показується банер «Вибачте, сталася помилка при оцінці. Ваші
  відповіді збережено.» з кнопкою «Спробувати ще раз»; стан тесту не скидається.
- `localStorage` очищається лише після успішної відповіді API.
- Zod-схема дозволяє до 80 відповідей, щоб довгі адаптивні тести не падали з 400.
- Опційний серверний `pending_evaluation` не реалізовано — винесено за межі задачі.
