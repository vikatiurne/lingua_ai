# 31.5 — Fallback Exercise Resilience

**Епік:** E8 — Evaluation / E7 — Exercise
**Розмір:** M (2–3 год)
**Залежності:** 27, 29, 30, 31
**Статус:** ✅ Done
**Гілка:** `fix/20.4-level-test-ux`

> ⚠️ **ПРОБЛЕМА:**
> Fallback-вправа з історії (`/exercise/[id]?from=history`) втрачала введені
> відповіді після F5, показувала порожній еталон і падала з 500 під час перевірки.
> Причина 500 — не Zod, а недоступність усіх AI-провайдерів; fallback-речення
> також не мали придатного `reference`, бо шаблони містять лише англійські
> приклади без українських перекладів.

---

## 🎯 Мета

Зробити fallback-вправу передбачуваною: зберігати чернетку відповідей між
перезавантаженнями, коректно показувати відсутній еталон, валідовувати дані
перед оцінкою та повертати зрозумілі 400/503 замість загального 500.

## ✅ Acceptance Criteria

### 1. Fallback-генерація та еталон
- [x] Кожне fallback-речення має унікальний `id` (`crypto.randomUUID()`).
- [x] Fallback використовує лише напрямок `en_uk`, бо приклади в шаблонах англійські.
- [x] Замість порожнього `reference` зберігається маркер
      `[Еталон недоступний в аварійному режимі]`.
- [x] Кількість fallback-речень не перевищує кількість прикладів; дублікати не створюються.
- [x] Оцінювач ігнорує маркер під час перевірки, але не стирає його з БД.

### 2. UI розбору
- [x] Порожні `reference`/`explanation` не рендеряться.
- [x] Маркер fallback показується як пояснювальна примітка, а не як «Правильно: …».
- [x] «Ваш варіант допустимий» не показується без реального еталона.

### 3. Чернетка відповідей
- [x] `ExerciseForm` зберігає відповіді в `localStorage` під ключем
      `exercise_[id]_draft` після кожного введення.
- [x] При завантаженні чернетка відновлюється; враховуються лише відомі `sentenceId`.
- [x] Після F5 відповіді не губляться.
- [x] Після успішної оцінки чернетка очищається.
- [x] При помилці оцінки відповіді та чернетка залишаються.

### 4. Валідація та помилки API
- [x] Спільний валідатор перевіряє `id`, `source`, `direction`, `reference`,
      унікальність `id` і типи необов'язкових полів.
- [x] Невалідні `sentences` → 400 «Некоректні дані вправи. Спробуйте створити нову.»
- [x] Порожній/відсутній `userAnswer`, невідомі або дубльовані `sentenceId` → 400.
- [x] Недоступність усіх AI-провайдерів → 503 із повідомленням, що відповіді збережено.
- [x] Форма показує текст помилки з API, а не лише загальний статус.
- [x] `pnpm typecheck`, `pnpm test`, `pnpm build` проходять.

## 🧩 Реалізація

### 1. Fallback reference

`lib/exercise/fallback.ts` містить `FALLBACK_REFERENCE`,
`buildFallbackSentences(examples, count)` та `isFallbackReference()`.
Builder бере `examples.slice(0, count)`, тому 1 приклад + запит 3 речень дає
1 речення без дублів. `generator.ts` використовує цей builder; локальну копію видалено.

### 2. Оцінювач

`evaluator.ts` перед оцінкою парсить `sentences` через спільний валідатор.
Маркер fallback замінюється на `""` для промпту та скорингу, але
`referenceById` повертає оригінальний маркер у `updatedSentences`, щоб
повторне оцінювання не стирало його. Якщо AI не дав пояснення — зберігається
«Оцінено без AI».

### 3. Чернетка

`ExerciseForm` ініціалізується збереженими на сервері `userAnswer`, потім
відновлює `localStorage`-чернетку. Ефект збереження активний лише після
завантаження чернетки, щоб не перезаписати її порожнім станом. Після успішної
оцінки ключ видаляється, після помилки — ні.

### 4. API

- `PATCH /answers`: валідує структуру вправ, `sentenceId`, повноту відповідей.
- `POST /evaluate`: `ExerciseValidationError` → 400; `AIServiceError` → 503.
- `lib/validation/exercise.ts`: `userAnswer` обов'язковий, trim + min(1).

## 🧪 Перевірка

```bash
pnpm --filter web typecheck
pnpm --filter web test -- --run
pnpm --filter web build
```

Fallback з одним прикладом покритий тестом: повертає 1 речення, унікальний `id`,
`direction: "en_uk"` і маркер `reference`. Валідатор покритий тестами на
відсутній `id`/`reference`, дублікати та порожні відповіді.

---

## ⚠️ Обмеження

Fallback-вправи, створені до цієї задачі, не мігруються: у них `reference`
лишається порожнім, і UI просто приховує цей рядок. Маркер з'явиться лише в
нових fallback-вправах.
