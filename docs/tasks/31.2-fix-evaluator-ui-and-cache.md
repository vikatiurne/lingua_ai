## 🔧 Приклад коду для нормалізації (у `evaluator.ts`)

Агент має зробити щось подібне перед відправкою в AI:

```ts
// Helper function for text normalization
function normalizeText(text: string): string {
  return text
    .toLowerCase()
    .replace(/[.,!?;:"()]/g, "") // Remove punctuation but KEEP apostrophes
    .replace(/\s+/g, " ")        // Replace multiple spaces with a single space
    .trim();
}

// Usage before calling AI:
const cleanUserAnswer = normalizeText(sentence.userAnswer);
const cleanReference = normalizeText(sentence.reference);
```

## 📝 Нотатки

Заповнено після завершення.

- **AC1–AC3 виконано без відступів.** Нормалізація — у `lib/exercise/evaluator.ts` (лише для промпту; у БД, як і раніше, зберігається trimmed-відповідь). Невірна відповідь на результаті — `text-destructive` без `line-through`. Бейджик: `topicScore >= 80 && grammarScore >= 80` → Passed (`--success`), інакше → Needs Practice (`--destructive`).
- **Відхилення: `...` виключено з нормалізації.** За прикладом із задачі `normalizeText("...")` → `""`, що зламало б розпізнавання пропущених відповідей AI-ом (`normalizeForPrompt` залишає `...` недоторканим).
- **AC4 — кеш уже враховував кількість речень.** Промпт генерації з початку містив `ukEnCount`/`enUkCount` (`generate-exercise.ts`), а кеш-ключ `ai:<hash>` хешує повний текст промпту (`cached.ts`) — зміна кількості вже мала давати cache miss. Для надійності все одно додано явний `sentenceCount` у `AICompletionOptions` → `buildCacheKey`; `generator.ts` передає `ukEnCount + enUkCount`.
- **Якщо симптом «старих речень» відтвориться і після цього** — причина не в `ai:`-кеші. Найбільш імовірне пояснення: **error recycling** (при регенерації AI включає 3–5 минулих помилок — це фіч, не баг), або **fallback** (якщо AI недоступний, повертаються ті самі examples зі шаблону). Верифікувати в рантаймі.
