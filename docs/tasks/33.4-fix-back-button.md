## 🎯 Мета

Заборонити повторне проходження вже оціненої вправи (статус `evaluated`) та виправити навігацію.

---

## ✅ Acceptance Criteria

### 1. Клієнтська навігація (Заміна push на replace)

- [x] У компонентах, де відбувається редірект на сторінку результатів після успішної оцінки (у `components/exercise/exercise-form.tsx` та `components/exercise/pdf-check-form.tsx`), замінити `router.push('/exercise/[id]/result')` на `router.replace('/exercise/[id]/result')`.
- [x] Це видалить сторінку форми з історії браузера, тому кнопка "Назад" вестиме на сторінку до початку вправи (наприклад, на `/plan`).

### 2. Серверний захист (Сторінка вправи)

- [x] У файлі `app/(dashboard)/exercise/[id]/page.tsx` додати перевірку статусу:

  ```ts
  if (exercise.status === 'evaluated') {
    redirect(`/exercise/${exercise.id}/result`);
  }

  □ Це гарантує, що навіть при прямому переході за посиланням на вже оцінену вправу, користувача буде перекинуто на результати.
  ```

3. Захист на рівні API (Бонус)
   ☑ У роуті app/api/exercise/[id]/answers/route.ts (PATCH) додати перевірку: якщо вправа вже має статус evaluated, повертати помилку 400 Bad Request (не дозволяти змінювати відповіді).
   🔧 Хрупкі місця
   redirect vs notFound: У Next.js App Router для серверних компонентів використовується функція redirect з next/navigation. Переконайтеся, що вона правильно імпортована.

Кеш браузера: Іноді браузер може кешувати сторінку форми (BFCache). Якщо router.replace не допомагає на 100%, можна додати export const dynamic = 'force-dynamic' на сторінку вправи, щоб вона завжди запитувала свіжі дані з сервера.
