Зробити розбір передбачуваним:
- модель повертає **тільки сирі виправлення** `wrong → correct` + порушення теми, без категорій;

- кожен `...` дає переклад і картку в словнику;
- `en_uk` з `...` ніколи не вважається засвоєною темою;
- оцінка теми рахується з вердиктів по реченнях, а не з арифметики моделі.

## 🔧 Хрупкі місця

### 1. `...` не можна нормалізувати
Будь-яка очистка тексту перед промптом має зберігати `...` / `…`, інакше пропуск зникає й модель не бачить, що слово не перекладене.

### 2. Довіряти моделі не можна
- Вона може не повернути корекцію для реальної помилки → працює коригувальний ретрай (`findViolations`).
- Вона може назвати синонім помилкою → пакетна перевірка замін/перекладів.
- Вона може вигадати слово → кожне слово звіряється з англійським реченням і списком реально відсутніх слів.

### 3. `en_uk` і `uk_en` — різна логіка
- `uk_en`: перевіряємо англійську відповідь, українські помилки не існують.
- `en_uk`: оцінюємо лише зміст; `...` — це не «дрібна помилка», а незасвоєна тема.
- Перевірка «слово вже передано» для `uk_en` не запускається: вона порівнює англійське слово з українським джерелом і дає хибні результати.

### 4. Оцінки
`topicScore` і `grammarScore` не беруться з моделі як є — вони виводяться з вердиктів по реченнях. Це навмисно: слабші моделі погано рахують відсотки.

### 5. Без міграцій
Схема БД не змінювалася; жодних `prisma migrate` для цієї задачі не потрібно.
