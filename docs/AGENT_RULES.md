### Правило:

Якщо у задачі або контексті немає чіткої відповіді — **зупинись і спитай**.

### Приклади, коли треба спитати:

- Треба створити файл, якого немає у списку.
- Не зрозуміло, який саме JSON-формат має повертати промпт.

- ❌ Не вигадувати структуру БД, якої немає в контексті.

- ❌ Не робити «як краще», якщо в задачі сказано «як простіше».

## 7. Стиль коду

- **TypeScript** — строгий режим, без `any` (якщо не уникнути — коментар чому).
- **Server Components** — за замовчуванням. `"use client"` — тільки якщо треба інтерактив.
- **Tailwind** — для стилів. Без CSS-модулів, styled-components.
- **shadcn/ui** — для UI-компонентів. Не додавати інші UI-бібліотеки.
- **Named exports** — для компонентів (`export function Foo`), не default.
- **Файли** — kebab-case для папок (`app/exercise/[id]/`), PascalCase для компонентів (`ExerciseCard.tsx`).
- **Мова коду** — англійська. Назви функцій, змінних, типів — англійською.

### 7.1. Чисті компоненти

**Принцип:** компонент — це **функція від props до JSX**. Все інше — поза компонентом.

**Що має бути в компоненті:**
- ✅ Рендер JSX на основі props.
- ✅ Мінімальна логіка для відображення (форматування, обчислення похідних значень).
- ✅ Умовний рендер — якщо це частина відображення.

**Що НЕ має бути:**
- ❌ `fetch` / запити до API.
- ❌ Прямий доступ до `process.env` (окрім `NEXT_PUBLIC_*` URL).
- ❌ Бізнес-логіка (розрахунки, трансформації даних).
- ❌ Робота з БД, Redis, файловою системою.
- ❌ Запити до AI-провайдерів.
- ❌ `console.log` (окрім тимчасового дебагу — прибрати перед комітом).
- ❌ Мутації props.
- ❌ Складна логіка в JSX (> 3 рівнів вкладеності — винести).

**Приклад:**

```tsx
// ❌ Погано
function ExerciseCard({ exerciseId }: { exerciseId: string }) {
  const [exercise, setExercise] = useState(null);
  useEffect(() => {
    fetch(`/api/exercise/${exerciseId}`).then(r => r.json()).then(setExercise);
  }, [exerciseId]);
  // ...
}

// ✅ Добре
async function ExercisePage({ params }: { params: { id: string } }) {
  const exercise = await getExercise(params.id);
  return <ExerciseCard exercise={exercise} />;
}

function ExerciseCard({ exercise }: { exercise: Exercise }) {
  return (
    <div>
      <h2>{exercise.topic}</h2>
      <p>{exercise.subtopic}</p>
    </div>
  );
}
```

### 7.2. Єнуми та константи

**Не використовувати `enum` з TypeScript.** Використовувати `as const` об'єкти.

```ts
// ✅ Добре
export const CEFR_LEVEL = {
  A1: "A1",
  A2: "A2",
  A2_PLUS: "A2_PLUS",
  B1: "B1",
  B1_PLUS: "B1_PLUS",
  B2: "B2",
  C1: "C1",
  C2: "C2",
} as const;

export type CEFRLevel = (typeof CEFR_LEVEL)[keyof typeof CEFR_LEVEL];

export const CEFR_LEVEL_LABELS: Record<CEFRLevel, string> = {
  A1: "Початківець",
  A2: "Елементарний",
  A2_PLUS: "Просунутий елементарний",
  B1: "Середній",
  B1_PLUS: "Міст до B2",
  B2: "Вище середнього",
  C1: "Просунутий",
  C2: "Володіння на рівні носія",
};
```

**Де зберігати:** `packages/shared/src/enums/`.
**Синхронізація зі Strapi:** значення мають бути ідентичні.

**Правило:** UI показує `"A2+"` тільки через `CEFR_LEVEL_LABELS[CEFR_LEVEL.A2_PLUS]`. У коді — тільки `A2_PLUS`.

### 7.3. Робота з JSON-файлами слотів

- JSON-файли `slots_*.json`, `slots_nouns_*.json`, `templates_*.json` — **джерело істини**.
- **Не змінювати** структуру без явної вказівки.
- **Не редагувати** вручну — якщо треба зміна, окрема задача.
- Ссылки формату: `<file>#/slots/<category>/<subcategory>/<slot>`.

### 7.4. Робота з AI

- **Всі промпти** — у `lib/ai/prompts/*.ts`. Не хардкодити у компонентах.
- **API-ключі** — тільки через `process.env`.
- **Fallback:** OpenRouter → Gemini → DeepSeek.
- **Cross-check:** для критичних завдань — дві моделі.
- **Timeout:** 30 секунд.
- **Retry:** 2 спроби.
- **Логування:** всі запити/відповіді у БД або файли.
- **Ніколи не логувати** персональні дані у промптах.

### 7.5. Робота з Redis

- **Ключі** — за схемою: `ai:<hash>`, `ratelimit:<userId>:<minute>`, `session:<id>`.
- **TTL** — обов'язково для всіх ключів.
- **Fallback:** якщо Redis недоступний — не падати, працювати без кэшу.
- **Ніколи не зберігати** персональні дані довше TTL.

### 7.6. Робота з БД

- **Prisma** — ORM. Ніяких raw SQL без необхідності.
- **Міграції** — через Prisma.
- **Транзакції** — для багатокрокових операцій.

### 7.7. Робота з PDF

- **Бібліотека:** `pdf-lib` або `pdfmake`.
- **Кирилиця** — обов'язкова підтримка.
- **Формат:** заголовок теми → список пропозицій → місце для рукописного перекладу після кожного.

### 7.8. Робота з графікою

**Що робить агент:**
- **Іконки UI** — тільки `lucide-react` (через shadcn/ui).
- **Логотип** — SVG-компонент у React.
- **Favicon** — `app/icon.svg` (Next.js підхопить автоматично).
- **OG-image** — генерувати кодом через `ImageResponse` з `next/og`.
- **Landing-графіка** — CSS-градієнти або прості SVG.

**Що НЕ робить агент:**
- ❌ Не генерує PNG/JPG через AI-сервіси.
- ❌ Не використовує зовнішні URL зображень без явної вказівки.
- ❌ Не додає Lottie, GIF, відео.
- ❌ Не створює ілюстрації до кожної теми/уроку.

### 7.9. Скриншоти для README

**Мета:** візуальна витрина проєкту в GitHub. Зайшовши в репозиторій, людина одразу бачить, що це за застосунок.

**Правила:**
- Скриншоти робляться **тільки для 5 ключових UI-екранів**: landing, login, dashboard, exercise, evaluation.
- Зберігаються в `docs/screenshots/` з простою назвою: `01-landing.png`, `02-login.png`, `03-dashboard.png`, `04-exercise.png`, `05-evaluation.png`.
- Показуються в `README.md` як галерея (таблиця з картинками).
- Для решти задач скриншоти **не потрібні**.

**Хто робить:**
- Агент **не генерує** зображення і **не робить** скриншоти автоматично.
- Скриншот робить користувач вручну або через Playwright-скрипт (коли буде налаштовано).
- Агент **готує місце**: створює папку `docs/screenshots/` і додає посилання в `README.md`.

**Що НЕ робити:**
- ❌ Не робити скриншот на кожну задачу.
- ❌ Не робити більше 5–7 скриншотів на весь проєкт.
- ❌ Не використовувати імена типу `screenshot-2024-01-15-15-30-45.png`.
- ❌ Не класти у git, якщо файл > 500 КБ (стискати).

## 15. Робота з Redis (для практики)

Redis використовується для:
1. **Кэш відповідей AI** — TTL 24 год.
2. **Rate limiting** — обмеження запитів на користувача.
3. **Очереді фонових завдань** (BullMQ) — PDF, email.

**Правила:**
- Всі ключі — з префіксом (`ai:`, `ratelimit:`, `bull:`).
- TTL обов'язковий.
- Якщо Redis недоступний — fallback без кэшу.
- Ніколи не зберігати персональні дані довше TTL.
